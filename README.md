# Спецификация консольного ToDo-приложения

## 1. Назначение

Приложение предназначено для управления списком задач в консоли.
Пользователь может добавлять задачи, просматривать список, удалять
задачи и изменять их статус выполнения.

В рамках исходного задания также рассматривалась возможность поиска
задач. В текущей реализации, полученной в ходе выполнения практикума,
функция поиска отдельно не реализована; она относится к исходному
пользовательскому запросу и требует отдельного уточнения/реализации.

## 2. Формат работы

-   Приложение работает в консоли.
-   Взаимодействие с пользователем выполняется через текстовое меню.
-   Данные хранятся только во время работы программы.
-   После завершения программы список задач не сохраняется.
-   Основные действия реализованы отдельными функциями.

## 3. Структура задачи

Каждая задача представлена объектом со следующими полями:

  Поле          Тип      Назначение
  ------------- -------- --------------------------
  `title`       `str`    Название задачи
  `completed`   `bool`   Статус выполнения задачи

При добавлении новой задачи значение `completed` устанавливается в
`False`.

## 4. Основные функции

### 4.1. Добавление задачи

Функция:

``` python
add_task(tasks, title)
```

Назначение: добавить новую задачу в список.

#### Правила

1.  `title` должен иметь тип `str`.
2.  Из начала и конца названия удаляются лишние пробельные символы.
3.  Внутренние пробелы между словами сохраняются.
4.  После удаления пробелов название не должно быть пустым.
5.  При корректном вводе задача добавляется в список.
6.  Новая задача получает статус `completed = False`.

#### Корректные примеры

``` text
"Учиться"
"   Проект   "
"Разобрать тесты"
```

После обработки:

``` text
"Учиться"
"Проект"
"Разобрать тесты"
```

#### Некорректные значения

``` text
""
" "
"     "
"\t"
"\n"
"\t\n"
None
123
12.5
True
[]
{}
```

Для пустого или состоящего только из пробельных символов названия
возникает `ValueError`.

Для значения неправильного типа возникает `TypeError`.

При ошибке список задач не должен изменяться.

## 5. Просмотр списка задач

Функция:

``` python
show_tasks(tasks)
```

Назначение: вывести текущий список задач в консоль.

Если список пуст, выводится сообщение:

``` text
Список задач пуст.
```

Для каждой задачи выводятся:

-   порядковый номер;
-   статус;
-   название.

Пример:

``` text
1. [ ] Учиться
2. [✓] Проект
```

Обозначения:

-   `[ ]` --- задача не выполнена;
-   `[✓]` --- задача выполнена.

## 6. Удаление задачи

Функция:

``` python
delete_task(tasks, index)
```

Назначение: удалить задачу по индексу.

Правила:

-   индекс должен находиться в диапазоне существующих элементов;
-   при корректном индексе задача удаляется;
-   при недопустимом индексе список не изменяется;
-   при недопустимом индексе выводится сообщение
    `Неверный номер задачи.`.

В пользовательском меню номер задачи начинается с `1`, поэтому перед
вызовом функции введённый номер преобразуется в индекс путем вычитания
`1`.

## 7. Изменение статуса задачи

Функция:

``` python
toggle_task(tasks, index)
```

Назначение: изменить статус задачи на противоположный.

Правила:

-   `False` изменяется на `True`;
-   `True` изменяется на `False`;
-   при недопустимом индексе список не изменяется;
-   при недопустимом индексе выводится сообщение
    `Неверный номер задачи.`.

## 8. Главное меню

При запуске приложение предоставляет меню:

``` text
=== ToDo ===
1. Добавить задачу
2. Показать задачи
3. Удалить задачу
4. Изменить статус
5. Выход
```

### Обработка команд

  Команда   Действие
  --------- -------------------
  `1`       Добавление задачи
  `2`       Просмотр списка
  `3`       Удаление задачи
  `4`       Изменение статуса
  `5`       Завершение работы

Если пользователь вводит неизвестную команду, выводится:

``` text
Неизвестная команда.
```

При выборе удаления или изменения статуса приложение запрашивает номер
задачи.

Если вместо числа введено значение, которое нельзя преобразовать в
`int`, выводится:

``` text
Введите число.
```

## 9. Обработка ошибок

Приложение должно корректно обрабатывать некорректный пользовательский
ввод.

### Добавление

-   пустое название → ошибка `ValueError`;
-   название из пробелов → ошибка `ValueError`;
-   название из табуляции/перевода строки → ошибка `ValueError`;
-   значение неправильного типа → ошибка `TypeError`;
-   после ошибки список задач не изменяется.

В консольном интерфейсе ошибки добавления перехватываются и выводятся
пользователю в виде:

``` text
Ошибка: <описание ошибки>
```

### Удаление и изменение статуса

-   отрицательный индекс не считается допустимым;
-   индекс за пределами списка не считается допустимым;
-   пустой список обрабатывается без аварийного завершения;
-   при некорректном индексе состояние списка не изменяется.

## 10. Требования к тестированию

Для проверки приложения используются автоматические тесты с помощью
`pytest`.

Тесты должны проверять:

### Корректный ввод

-   `"Учиться"`;
-   `"   Проект   "`;
-   `"Разобрать тесты"`.

### Некорректный ввод

-   пустую строку;
-   строку из пробелов;
-   табуляцию;
-   перевод строки;
-   значения других типов.

Для каждого случая проверяются:

1.  входные данные;
2.  ожидаемый результат;
3.  соответствующее требование;
4.  возникающая ошибка, если она предусмотрена;
5.  неизменность списка после ошибки.

### Дополнительные проверки

Проверяется:

-   добавление нескольких задач;
-   начальный статус новой задачи;
-   удаление первой, последней и средней задачи;
-   удаление единственной задачи;
-   удаление при недопустимом индексе;
-   изменение статуса с `False` на `True`;
-   изменение статуса с `True` на `False`;
-   повторное изменение статуса;
-   работа со списком из нескольких задач;
-   вывод пустого списка;
-   вывод выполненных и невыполненных задач;
-   корректная нумерация задач.

## 11. Требования к состоянию данных

При успешном добавлении список задач изменяется путем добавления нового
элемента.

При ошибке добавления существующее состояние списка должно сохраняться
без изменений.

При удалении корректной задачи количество элементов уменьшается на один.

При изменении статуса название задачи и остальные задачи не изменяются.

## 12. Ограничения текущей версии

Текущая версия приложения является консольным приложением с хранением
данных только в оперативной памяти.

В текущем коде отсутствуют:

-   сохранение задач в файл или базу данных;
-   регистрация пользователей;
-   сетевое взаимодействие;
-   графический интерфейс;
-   отдельная функция поиска.

Функция поиска была указана в исходном пользовательском запросе, однако
конкретные требования к её поведению в задании не были полностью
определены, а в первой версии приложения из практикума она не входит в
обязательный набор функций. Поэтому перед её добавлением необходимо
уточнить правила поиска.

## 13. Итоговый состав приложения

По итогам выполнения технического задания приложение должно включать:

``` text
todo.py
test_todo.py
```

### `todo.py`

Содержит:

``` python
add_task(tasks, title)
show_tasks(tasks)
delete_task(tasks, index)
toggle_task(tasks, index)
main()
```

### `test_todo.py`

Содержит автоматические тесты для проверки функций приложения и
обработки ошибок.

## 14. Критерии готовности

Приложение считается соответствующим спецификации, если:

-   запускается в консоли;
-   предоставляет меню;
-   позволяет добавлять задачи;
-   корректно обрабатывает пробелы в названии;
-   не позволяет добавить пустое название;
-   корректно показывает список задач;
-   позволяет удалять задачи;
-   позволяет изменять статус задач;
-   корректно обрабатывает неправильные индексы;
-   не изменяет список при ошибочном добавлении;
-   автоматические тесты проверяют требования контракта `add_task`;
-   после выполнения тестов подтверждается корректность реализованных
    требований.
